Traveller reading — Anthropic API

Reading a traveller image sends the pages to Anthropic's API using your own key. It needs internet, so it will not work on a shop-floor machine that is offline. Everything else in this app runs with no network at all.

How the key is handled. It is stored in this browser's local storage and sent only to api.anthropic.com. It is never written into a saved .json, never into an exported .xlsx, and never leaves this machine anywhere else. It is stored in clear text, as browser storage always is — on a shared or kiosk machine, use Forget key when you finish. Use a key scoped to this purpose rather than an organisation-wide one, and rotate it if the machine changes hands.

GitHub sync

Saves PFMEA files to a GitHub repository so they follow you between machines, and lets you push a new version of the app itself. This sends data off this device — use a PRIVATE repository.

Export control — read before switching this on. Your standing rule is that drawing, part and feature data stays on this device. GitHub sync breaks that by design: it copies PFMEA content to a third-party cloud service. A private repository limits who can read it, but a private repo is not by itself an export-control determination. Image sync is off by default because drawings and travellers are the most sensitive thing this app holds — turning it on sends them too. Confirm with whoever owns export compliance at CAMCO before using this on ITAR work, and keep the token scoped to this one repository.
